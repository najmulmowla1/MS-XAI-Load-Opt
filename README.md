# MS-XAI-Load-Opt

**Reproducible research code for one-hour-ahead electricity consumption forecasting in Türkiye**

This repository accompanies *Leakage Safe Explainable AI Framework for Hourly Electricity Consumption Forecasting in Türkiye*. MS-XAI-Load-Opt is an **integrated forecasting and evaluation framework**, **not** a newly proposed forecasting algorithm.

The analysis combines hourly electricity-market data (2018–2023), time-derived predictors and prior-year Our World in Data (OWID) indicators. Model development uses expanding temporal validation folds for 2020, 2021 and 2022; the independent test period is 2023. The pipeline includes baseline and optimized model comparisons, feature-group ablations, SHAP attribution, conformal prediction intervals, dependence-aware statistical comparisons, and performance diagnostics.

## Repository structure

| Location | Purpose |
|---|---|
| [`steps/`](steps/) | **32 numbered experimental steps:** 1 dependency-installation shell script and 31 Python scripts, kept in their original execution order |
| [`run_pipeline.py`](run_pipeline.py) | Executes Python steps 02–32 **sequentially in a shared Python namespace** |
| [`verify_inputs.py`](verify_inputs.py) | Checks input dataset SHA-256 hashes, sizes, schemas and coverage without fitting models |
| [`requirements.txt`](requirements.txt) | Recorded package versions where available, plus remaining dependencies |
| [`metadata/`](metadata/) | Dataset fingerprints, source-to-script manifest, run settings and results recorded from an earlier execution |
| [`docs/`](docs/) | Methods, data provenance, replication and limitations |
| [`tests/`](tests/) | Automated source and repository-integrity tests |
| [`data/`](data/) | Local folder for input data (datasets are **not redistributed** here) |

**No `.ipynb` file is required or included.** The numbered scripts represent the original experiment stages. They are not designed to run individually, because later steps depend on variables initialized by earlier ones. Use `run_pipeline.py` rather than executing files separately.

## Data

Obtain the required files from the original sources described in [`docs/DATA.md`](docs/DATA.md) and place them at the following paths:

```text
data/
├── hourly_energy_data.csv
└── owid_energy_data.csv
```

The exact input snapshots used in the previously completed analysis were checked against the uploaded files, and their SHA-256 fingerprints are recorded in [`metadata/dataset_fingerprints.json`](metadata/dataset_fingerprints.json). The files themselves are not bundled in this public repository. Later upstream versions may not reproduce identical results.

## Setup and execution

Recommended starting environment: **Python 3.11**. The entire experiment has not been rerun in a fresh environment with these packaged scripts; some dependencies (especially TensorFlow and Prophet) can require platform-specific installation.

From the repository root:

```bash
python -m venv .venv
# Activate the environment: source .venv/bin/activate (macOS/Linux)
# or .venv\Scripts\activate (Windows)
python -m pip install -r requirements.txt

python -m unittest discover -s tests -v
python verify_inputs.py --data-dir data
python run_pipeline.py --data-dir data --output-dir results --check-only
python run_pipeline.py --data-dir data --output-dir results
```

To execute only the initial preprocessing and validation stages (for troubleshooting), after installing dependencies:

```bash
python run_pipeline.py --data-dir data --output-dir results --stop-after-step 10
```

**Step 01** (`steps/01_install_analysis_dependencies.sh`) is a convenience installer for Unix-like shells; it is not part of the Python runner. Installing `requirements.txt` manually is sufficient.

On a remote machine or cloud runtime, use explicit `--data-dir` and `--output-dir` paths. This workflow also runs in a Google Colab runtime through its terminal or shell commands; no Colab notebook is provided.

## Reported result provenance

The included `metadata/reported_run_summary.json` records the values from an **earlier completed execution** supplied with the research files, including the validation-selected XGBoost–Optuna/TPE configuration, 133 predictors, mean validation RMSE of **599.17 MWh**, and held-out 2023 test RMSE of **441.85 MWh**. Those numbers are not generated by the repository-integrity tests and **must not be represented as newly reproduced** until the full pipeline has been executed and the outputs reconciled against the article and its supplement.

Run outputs, including figures, fitted models, intermediate results and an Excel evidence workbook, are written to the selected results folder and excluded from version control by `.gitignore`.

## Important interpretation boundaries

- Forecast inputs are indexed at or before the forecast origin, but timestamp-based leakage control **does not prove real-time public availability** of every predictor.
- SHAP reports model attribution, not causal effects.
- The pretest validation protocol selects models; the 2023 holdout is for independent evaluation.
- Computing speed alone does not establish readiness for operational electricity-market deployment.
